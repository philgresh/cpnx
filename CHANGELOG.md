## [Unreleased]

### Added

- **Best-effort side-effect linting (`cpnx.linting`) — an *advisory* AST scan that flags decidability-corrosive I/O in enabling logic.** `cpnx` admits arbitrary Python callables in guards, arc `key`/`filter` selectors, and output-arc conditions, deliberately forfeiting the static decidability the ISO/IEC 15909-1:2019 high-level-net core enjoys. `lint_callable(func)` walks the callable's AST (reusing `cpnx.certification`'s source-recovery and name-resolution helpers) and returns `LintFinding`s in three categories: **network** (`requests`, `httpx`, `urllib`, `http`, `socket`, `smtplib`, …), **database** (`sqlite3`, `psycopg`/`psycopg2`, `sqlalchemy`, `pymysql`, `asyncpg`, `pymongo`, `redis`, …), and **nondeterminism** (`random` whole-surface, plus the *specific* non-deterministic members of the mixed-surface stdlib packages `time`, `datetime` (`now`/`utcnow`/`today`), `uuid` (`uuid1`/`uuid4`), and `secrets`, and a small by-name clock/entropy table for local-alias receivers). Detection resolves the called symbol **to the package that defines it**, so `import requests as r; r.get(...)` and `from requests import get; get(...)` resolve identically; whole-surface packages flag outright, mixed-surface packages flag only their listed members (so `datetime.timedelta`, `uuid.UUID("…")`, `time.strftime(…)` are **not** flagged), and names that collide with token-payload/dict methods (`.get`, `.execute`, `.connect`, `.time`) are excluded from the by-name table to avoid misfiring on a plain dict. This is the **third, softest** of `cpnx`'s confidence layers — below `cpnx.certification` (whitelist inline-safety proof, never raises) and `cpnx.sandbox.verify_callable_purity` (blocklist purity gate, raises) — and it fills the gap between them: findings emit as `CpnxLintWarning` (a dedicated, independently filterable category) at construction time, and a process-wide strict switch (`cpnx.set_strict(True)` or `CPNX_LINT_STRICT=1`) promotes them to `SideEffectLintError` for CI gating. It is **advisory, not a hard gate**, because sound static side-effect detection is impossible in a language with `getattr`, dynamic dispatch, monkeypatching, and late binding (Eghbali, Burk & Pradel, "DyLin: A Dynamic Linter for Python," *Proc. ACM Softw. Eng.* 2, FSE 2025) — a clock read or occasional lookup in a guard is legal, sometimes-intentional Python, so hard-rejecting it would break valid nets and overstate what static analysis can prove. Best-effort by construction: only the callable's **own body** is scanned (not transitively-called helpers), and fully dynamic dispatch is invisible. Paired with **dynamic invariant fuzzing** ([`tests/test_invariants_fuzz.py`](tests/test_invariants_fuzz.py), Hypothesis) that asserts no orphaned tokens outside sinks, quiescence within a step budget linear in token count, and by-design deadlock only in a negative-control net — the empirical counterpart for everything static analysis cannot see. The Concurrency Cafe grows a `build_cafe(hazards=True)` decidability-hazards station (a gallery of guards/keys/filters that smuggle network/database/clock/randomness reads into enabling logic) as the negative control; the base cafe stays lint-clean ([`tests/test_cafe_lint.py`](tests/test_cafe_lint.py)), and [`benchmarks/lint_cafe.py`](benchmarks/lint_cafe.py) prints the before/after report. See [`docs/adr/0007-best-effort-side-effect-linting.md`](docs/adr/0007-best-effort-side-effect-linting.md) ([#49](https://github.com/philgresh/cpnx/pull/49)).

- **Declarative colour-domain blast-radius (impact) analysis (`cpnx.analysis`) — a sound forward cone-of-influence slice, fused with the linter into one report.** ADR 0007's linter answers *which* transitions reach outside the decidable core; it does not bound *how far* a hazard's effect can spread. Since `cpnx` cannot decide which colours an arbitrary Python `action` produces (the same Halting-Problem wall), impact is **declared, not inferred**: a transition carries a new optional, purely-declarative annotation [`Transition.impacts_colors: frozenset[str] | None`][cpnx.Transition] naming the token colour domain(s) it mutates (e.g. `impacts_colors={"order", "refund"}`) — never evaluated at run time, no effect on firing. Any iterable of colour-name strings is coerced to a `frozenset` by `coerce_color_domain`; a **bare `str` raises `TypeError`** (pass `{"order"}`, not `"order"`); `None` (default) means *undeclared*, and an empty set is a distinct *narrowing* declaration. `trace_impact(net, transition_name, *, colors=None) -> ImpactMap` (also [`net.trace_impact(...)`][cpnx.PetriNet.trace_impact]) walks the static topology **forward** by BFS from the seed's **output** places, hopping place → consuming-transition → its output places, terminating on cycles (each transition expanded once; the seed never re-expanded). The COI gate is a **colour-set disjointness test**: a downstream place is pruned when its declared `color_set` is disjoint from the traced domain. The slice is deliberately **over-approximate** and thus sound — grounded in COI-SOUND (Telbisz et al., SPIN'25, Thm 1: an over-approximate slice never hides a reachable fault) and COALG-COI (Watanabe et al., ENTCS 164 (2006): the reduced model (bi)simulates the original): an **undeclared** origin traces *every* colour (no pruning), and a place with `color_set is None` (accepts any colour) is *always* included. So an `ImpactMap` (fields `origin`, `colors`, `places`, `transitions` with the seed excluded, `edges`; `.to_dict()` is JSON-serialisable and sorted) may over-name but never omits a genuinely-reachable node — it **bounds** risk, it does not prove its absence. `risk_report(net) -> dict` (also [`net.risk_report()`][cpnx.PetriNet.risk_report]) **fuses the two prongs**: it lints every transition's enabling inscriptions via ADR 0007's `lint_callable`, and for any transition that trips the linter *or* declares `impacts_colors` it attaches that transition's blast radius — one JSON-serialisable `{"findings": [...], "impact_maps": {...}}` object answering both "which transitions are hazards?" and "how far does each spread?". `to_dot(net, *, highlight_impact_from=<name>)` shades a blast radius into the DOT export (impacted nodes filled `#ffd9d9`, seed `#ff8080` with a heavier border; `None` leaves the rendering unchanged). `ImpactMap`, `trace_impact`, and `risk_report` are exported from the top-level `cpnx` package, and a `docs/cpn-invariants.json` records the grounding literature. Complexity is `O(V + E)` over places + arcs. The running demonstration is [`benchmarks/impact_cafe.py`](benchmarks/impact_cafe.py) (with [`tests/test_cafe_impact.py`](tests/test_cafe_impact.py)), the companion to `lint_cafe.py`. See [`docs/adr/0008-color-domain-impact-analysis.md`](docs/adr/0008-color-domain-impact-analysis.md).

- **The Concurrency Cafe is now a CPN-faithful topology, and `to_dot` renders place *roles* honestly.** The benchmark fixture previously showed many places with **no input arc**, obscuring how they filled. Two structural fixes make the net honest: a single **front door** `P_New_Order` — the one external source where a customer's order enters, written into `P_Ticket_Line` by a new `T_Take_Order` transition — and **explicit resource self-loops**, so each borrowing transition returns its permit through a matching output arc (a visible `M' = M − Pre + Post` borrow-and-return on the scales, grinders, group heads, and wands) instead of relying on the engine's implicit leftover-return. `to_dot` gains role-distinct rendering for the places whose tokens arrive or leave **off-arc**: a **resource pool** is a double circle filled `#dbe9ff` (seeded at construction); a **sink / terminal** and the net's **error place** are radial-gradient "wells" (an inset-shadow inverted cone a token falls into — the error place tinted salmon); an **external source** (arc in-degree 0) is dashed. Two off-arc token paths are now drawn dashed so no place looks isolated and no path is hidden: a pale, thin, `constraint=false` **dead-letter** side channel from every finite-`max_retries` transition to the error place, and a **`return (implicit)`** edge from any transition that borrows a permit without a matching output arc. Place labels de-emphasise counts (shown only when a place actually holds tokens) so the picture reads as a token's *valid paths*, not a marking snapshot; the legend lists only the encodings actually present. Benchmark drivers deposit through the new front door (micro-benchmarks that measure priority depth still target `P_Ticket_Line` directly, by design).

### Changed

- **Resource-permit returns are now *structural* by default — the engine auto-synthesizes the self-loop instead of returning permits off-arc.** cpnx returned a consumed resource permit (`Token.is_resource`) to its pool through two mechanisms: an author-declared `OutputArc(pool)` (CPN-faithful, mechanism 1), or — when no such arc existed — an implicit *leftover-return* that swept the permit back **outside the arc structure** (mechanism 2). Mechanism 2 made the marking effect `M' = M − Pre(t) + Post(t) + (auto-returned resources)`, a last term expressed by no arc, so a purely structural reading of the net was **wrong for pools**: `to_dot` could not draw the return (pools looked sourceless), `analysis.trace_impact` (ADR 0008) walked `transition.outputs` and so never saw a borrowing transition impact its pool, and P-invariants / boundedness-by-inspection did not hold from the arcs alone — the ADR 0008 caveat, and what #50's dashed `return (implicit)` edge papered over cosmetically. [`PetriNet.validate`][cpnx.PetriNet.validate] now **synthesizes the missing arc**: for every transition borrowing from a [`ResourcePlace`][cpnx.ResourcePlace] via an `InputArc` with no matching `OutputArc`, it appends an `OutputArc(pool)` marked [`synthesized=True`][cpnx.OutputArc], converting mechanism 2 into mechanism 1 with no author change. It is **behaviour-preserving** (permits were already always returned on success — only the *representation* of the return changes, off-arc sweep → on-arc deposit) and **non-breaking** (no warning, no migration). Synthesis is one-time and idempotent, triggered before the first firing or introspection from every entry point that needs it — `validate` (hence `run`), `step` (hence `drive_to_quiescence`), `to_dot`, `trace_impact`, `risk_report` — and re-armed when a place or transition is added. **Overrides:** declaring your own `OutputArc(pool)` already suppresses synthesis for that pool, and [`Transition(auto_return_resources=False)`][cpnx.Transition] suppresses it entirely (keeping the raw implicit return). **Left on the implicit path** (still correct, just not structural): `consume_all` resource borrows (a fixed-count arc cannot express "return however many you drained"), asymmetric-count borrows (already have a matching output arc by name), and the failure/rollback return (a failed firing must return the permit regardless of the self-loop). `_return_leftover_resources` is retained for exactly those cases and is a no-op for the common synthesized one. See [`docs/adr/0009-structural-resource-return.md`](docs/adr/0009-structural-resource-return.md).

- **`to_dot` pins terminal places to the sink rank, so the flow reads left-to-right end to end.** A place with incoming tokens but **no outgoing arc** (nothing consumes from it) is where the flow ends — a `SinkPlace`, or the dead-letter bin whose only edges are the off-arc, `constraint=false` (hence rank-less) dead-letter channels. Such a bin previously floated at rank 0 (far left, beside the sources), because Graphviz had no constraining edge to place it. `to_dot` now emits a `{ rank=sink; ... }` group for every terminal place, inferred purely from the arc structure (out-degree 0 while produced, or the `error_place`) with no per-net hard-coding, so endpoints like the cafe's `P_Served` and `P_Trash_Can` land at the far right where they belong. The cafe fixture (`benchmarks/cafe`) also now showcases all three resource-return modes at once — explicit (`P_Digital_Scales`), synthesized (`P_Burr_Grinder`, `P_Espresso_Machine`), and implicit/opt-out (`P_Steam_Wand`, drawn as the dashed `return (implicit)` edge) — so it demonstrates default *and* explicit behaviour in one net.

## [0.5.0] — 2026-07-27

### Added

- **Incremental enablement scheduler — the per-step transition scan is now `O(K)`, not `O(T)`.** Before this change every `step()`, `is_quiescent()`, and `is_dead()` looped over **every** registered transition (`_enabled_transition_bindings` / `_is_transition_potentially_enabled` / `_is_transition_enabled` over `self.transitions.values()`), resolving a fresh binding for each and then firing one — so a single step was `O(T)` in the transition count `T`, a `K`-firing run `O(K·T)`, all under the single global engine lock (the lock-hold time that starves the `ThreadPoolExecutor` on a wide fan-out net). The engine now maintains an incremental scheduler: a static reverse-routing table (`_input_routing`: place → transitions with an `InputArc` on it; `_output_routing`: place → transitions with an *unconditional* `OutputArc` on it) plus a per-place dirty set (`_dirty_places`), so a step re-evaluates only the `K` transitions routed from the places the last firing actually mutated. Selection is `O(1)` — a `_rng.choice` over the minimum non-empty priority bucket — and `is_quiescent()`/`is_dead()` are `O(1)` for untimed nets (`not _potentially_enabled` / `not _enabled_bindings`), which lifts `run()`'s per-iteration ceiling, not just `step()`'s. Measured by [`benchmarks/bench_transition_scan.py`](benchmarks/bench_transition_scan.py): the `scan us` probe (1-of-`T` enabled) flattens from a linear climb to a constant ~0.6 µs, and the drive's `us/step` from linear to a constant ~33 µs (total drive `O(T²)` → `O(T)`), both growth factors ~1.0 across `T` doubling 50→1600.

  **Eligibility gate and full-scan fallback (`_incremental_eligible`).** The fast path engages only when the net has no clock-driven re-enablement (`not _has_timed_features` — no `PacedResourcePlace`, no `settle_secs > 0` arc) **and** no transition uses effective `BindingPolicy.RANDOM`/`PRIORITY`. Otherwise the engine falls back to the original full-scan methods, **unchanged and byte-identical** to before. The `RANDOM`/`PRIORITY` exclusion is a determinism guarantee: those policies draw the seeded RNG *during binding resolution, per enabled transition, per step*, so resolving a different count of them would shift the seeded stream and break the pinned golden sequence in [`tests/test_seeded_determinism.py`](tests/test_seeded_determinism.py) (which therefore runs on the fallback path and passes identically). `LEGACY`/`FIRST` draw RNG only for the scheduler's own tie-break, whose stream advance depends on the candidate *count* — reproduced exactly by the maintained enabled set. The gate re-evaluates when `net.binding_policy` is reassigned, so mutating the net-level default after construction cannot leave a search-policy net on the fast path.

  **Four re-enablement hazards a naive dirty set would miss, all handled:** (a) **back-pressure release** — consuming from a place can free output capacity for a transition whose *output* arc targets it, covered by dirty-on-consume + `_output_routing`, plus `_capacity_blocked` for an *out-of-band* `place.retrieve()` the dirty set never sees; (b) **retry re-arm** — a retry-delayed rollback token becomes available purely as time passes, handled on the fast path by a `_reactivation` min-heap that re-dirties the place when `retry_delay` elapses; (c) **external-state callables / source transitions** — a `guard`/`key`/`filter` may read a rebindable global or free variable (certification's documented late-binding rule permits it — e.g. `guard=lambda toks: gate_open`), and an input-less source transition routes from no place, so both are folded into an always-re-evaluated `_volatile_transitions` set; (d) **cross-process determinism** — reconcile re-evaluates the affected transitions in registration order (`_transition_order`), not hash-seed-randomized `set` order, so a seeded net fires identically across processes. See [`docs/adr/0006-incremental-enablement.md`](docs/adr/0006-incremental-enablement.md) and [`tests/test_incremental_enablement.py`](tests/test_incremental_enablement.py).

### Deprecated

- **`BindingPolicy.LEGACY` is deprecated and will be removed in v0.6.0**, including as the default for `PetriNet(binding_policy=...)` and the implicit default a `Transition` inherits when its own `binding_policy` is left `None`. `LEGACY`'s head-of-queue behavior was retained as the default through the migration window described in [`docs/adr/0001-combinatorial-binding-search.md`](docs/adr/0001-combinatorial-binding-search.md); `BindingPolicy.FIRST` is a strict superset — identical selection whenever the head token already satisfies the guard, plus the head-of-line fix when it doesn't — and is free (no search) for guard-free transitions, so there is no remaining case where `LEGACY` behaves differently in a way worth keeping. Migrate by passing `binding_policy=BindingPolicy.FIRST` explicitly wherever `LEGACY` is relied on today, including at `PetriNet` construction.

### Fixed

- **A raising certified `InputArc.key` no longer disables that arc's place key-index permanently — it re-arms once selection recovers.** A **certified** `key` is served from a persistent `(key, seq)` min-heap on the place (`places._KeyIndex`), which is what makes a deep keyed drain ≈ O(N log N) instead of O(N² log N) (#30). That heap **self-disables** if the key raises on a single token — or two keys are mutually incomparable — falling back to the per-firing filter+sort, which produces identical results (so the regression was invisible). The disable used to be **one-way**: `register_key_index` rebuilt only on a *different* `key_fn` identity and `_ensure_key_index` re-registered only when `arc.key` changed identity, so one malformed token reverted that arc to the slow path for the life of the net. Removing the offending token restored correctness but left the performance regression, with nothing reporting it — and #33's fault message told the operator the fault was clearable, which was true for correctness but not for performance. The disable is now reversible: `_KeyIndex` gains `rearm()` (re-enable and back-fill from the ready set, re-disabling if a token still can't be keyed), exposed via `_TokenStore.rearm_key_index` / `Place.rearm_key_index`. The engine tracks arcs whose index disabled on a *reported* selection fault (`_key_index_disabled_arcs`) and re-arms via `Place.rearm_key_index` the next time `_order_available` selects successfully for that arc — so the fast path recovers once the offending token is gone. A **flapping** key (one that raises intermittently) cannot thrash the heap: a rebuild happens **at most once per `_KEY_INDEX_REARM_MIN_DEPOSITS` deposits** (the deposit clock is the store's monotonic `_next_seq`), and never permanently surrenders the fast path. The healthy path is untouched — the tracking set is empty for a net whose keys never raise, so `_order_available`'s success path pays only a set-membership test. Scope is the reported-fault recovery edge: a `key` that raises only on tokens its `filter` rejects disables the index silently (no fault is reported) and is left as-is; a raising `filter` never touches the index, so this is `key`-specific. The #33 `on_error` message no longer claims the disable is permanent. Regression tests in [`tests/test_key_index.py`](tests/test_key_index.py) (`TestKeyIndexRearm`) assert the *index* is serving again (`peek_by_key` non-`None`, `key_index_disabled` `False`) after recovery, plus the rate-limit and re-disable guards. Resolves [#34](https://github.com/philgresh/cpnx/issues/34); related [#30](https://github.com/philgresh/cpnx/issues/30), [#33](https://github.com/philgresh/cpnx/issues/33).

- **`drive_to_quiescence` no longer strands tokens inside a `SubstitutionTransition`'s subnet, and a subnet's internal cooldowns are now free to simulate.** Driving a net that contains a subnet on the **logical** clock silently produced a wrong result: tokens stuck in the subnet's input port (measured: 14 of 20), `is_quiescent()` reporting `True`, and a normal `DriveResult` returned. The cause was clock *value coupling* — the parent pushed its logical time onto the subnet via `advance_time` on every firing, but a `SubstitutionTransition` fires once per binding, so the second firing at the same parent instant moved the subnet clock backward-or-equal, which `advance_time` rejects; that `ValueError` surfaced as a firing failure and rolled the transition back, leaving the already-deposited token copy inside the subnet. It had never surfaced because the only subnet in the corpus (`benchmarks/cafe/stations/pastry_case.py`) was exercised only via wall-clock `run()`, where the coupling is a no-op.

  The fix separates the two things the old code conflated. A subnet's clock **value** is now isolated — the parent's logical time never crosses the port boundary, like all other parent context. Its clock **regime** (logical vs. wall) is instead **inherited** from how the parent is driven: under `drive_to_quiescence` the subnet is driven logically too, so its internal cooldowns/settles are jumped for free (deterministic, and cheap — the tight `drive_to_quiescence` loop, not `run()`'s wall-clock wait) on the subnet's *own* independent clock; under `run()` (production) the subnet runs on the wall clock, so real cooldowns are genuinely waited out. Net effect: simulating a subnet with real internal friction is now ~380× faster (a 0.05 s cooldown over 8 tokens: ~388 ms waited → ~1 ms jumped), while production timing is unchanged. `subnet_deadline_secs` bounds only the wall-clock path; a logically-driven subnet is bounded by `drive_to_quiescence`'s `max_ticks`/`max_spins`. Tradeoff: a *friction-free* subnet is ~20% heavier per firing under the logical driver (its clock machinery vs. `run()`'s), a simulation-only cost. The previously-tested behaviour that the parent pushes its clock *value* onto the subnet was itself the bug and has been removed. Regression tests in [`tests/test_subnet.py`](tests/test_subnet.py); per-firing cost, the driver-mode win, and the friction-free tradeoff are measured by [`benchmarks/bench_subnet.py`](benchmarks/bench_subnet.py).

## [0.4.0] — 2026-07-22

### Removed

- **String guards and arc expressions removed (BREAKING).** `guard=` and `InputArc`/`OutputArc` `expression=` now accept a `Callable` only; passing a `str` raises `TypeError` at construction, with a message pointing to the callable form and the config-via-closure pattern. The string-expression evaluator (`SandboxEvaluator.evaluate_compiled` and the string-eval entry point) was deleted. The former "two forms" model — a string whitelist-sandbox alongside a callable — is gone; callables are now the sole expression surface. Migration: replace `guard="expr"` with a lambda/`def`; parameterise from config by reading the value at construction time and closing over the immutable result (which certifies). See [`docs/adr/0003-inline-execution-and-string-removal.md`](docs/adr/0003-inline-execution-and-string-removal.md).
- **`InputArc.expression` removed (BREAKING).** The single `Callable[[list[Token]], list[Token]]` selection transform is replaced by two keyword-only, per-token fields: `key: Callable[[Token], object] | None` (a pure per-token sort key — eligible tokens are consumed in **ascending**/min-first key order, mirroring `Transition.binding_priority_key`, ties broken by insertion order via a stable sort; descending is `key=lambda t: -f(t)`) and `filter: Callable[[Token], bool] | None` (a pure per-token eligibility predicate — a rejected token simply stays in the place). The engine applies `filter`, then orders survivors by `key`, then consumes the first `count`; with neither set the arc is plain FIFO, unchanged. Each callable is purity-verified independently with its own inline-safe flag (`_key_inline_safe` / `_filter_inline_safe`) — a certified one runs inline under the engine lock, an uncertified one on the timeout-bounded expression pool, exactly as guards do (see the Unreleased "Inline fast path" entry above); uncertified `key`/`filter` remain fully allowed — but note they are evaluated **per token** over the whole available pool, so on a deep place an uncertified one costs a thread round-trip per token per enabling check, with a worst-case lock-hold of `len(place) * expr_timeout_secs` that `binding_search_limit` does **not** bound (it truncates candidate *bindings*, downstream of selection). A guard, by contrast, is bounded at one evaluation per candidate binding. Certifying a selection callable matters most on deep places. Relatedly, `expr_timeout_secs` bounds a `key`'s *extraction* but not the **comparisons** between the values it returns, since the sort runs inline under the lock — return plain comparables. `filter` gets the same construction-time annotated-`-> bool` check as `Transition.guard`/`OutputArc.condition`; `key` does not, since it returns an arbitrary comparable rather than `bool`. A `key`/`filter` that raises, or a `key` whose values are mutually incomparable, makes the arc unsatisfiable for that firing, exactly as a raising `expression` did before. Migration: `InputArc(expression=lambda tokens: sorted(tokens, key=f))` → `InputArc(key=f)`; `InputArc(expression=lambda tokens: [t for t in tokens if p(t)])` → `InputArc(filter=p)`; a combined sort-then-filter callable → pass both `key=` and `filter=` (the engine always filters *then* sorts, regardless of the order in an old combined callable — re-check equivalence if the old callable filtered after a positional sort). An `expression` that performed an arbitrary `list[Token] -> list[Token]` transform that is neither a sort nor a filter (e.g. positional truncation, or an order depending on relationships between tokens rather than each token's own value) has **no direct equivalent** — this is by design, since exactly that opacity made the transform unindexable. **`consume_all=True` ignores both `key` and `filter`** — a draining arc takes the whole available pool in FIFO order, so a token the `filter` rejects is still consumed; this preserves exactly what `consume_all` did to `expression`. Because that combination is never meaningful, constructing (or reassigning into) such an arc now emits a `UserWarning` naming the ignored parameter(s) — engine behavior is unchanged, the documented bypass is merely audible at the call site. Silence it with `warnings.filterwarnings("ignore", message="consume_all=True ignores")`. For "drain everything eligible", use a large `count` instead of `consume_all`. **This is the API/correctness half only: draining a deep keyed place is still `O(N^2 log N)`** (the per-firing filter+sort in `engine.py::_order_available` still re-scans and re-sorts the whole pool every firing); the per-token `key` makes a persistent per-arc key-index *possible*, but that index is not part of this change. See [`docs/adr/0004-arc-selection-key-filter.md`](docs/adr/0004-arc-selection-key-filter.md) and [issue #25](https://github.com/philgresh/cpnx/issues/25).

### Added

- **A raising `InputArc.key`/`filter` now reports through `on_error`.** Previously a selection callable that raised made its arc unsatisfiable *silently*: the transition simply looked disabled, `run()` reached quiescence with work still sitting in the place, and nothing was logged. The engine signals every other comparable degradation — `on_binding_search_exhausted`, and a wholly-broken `binding_priority_key` — so selection was the odd one out, and the per-token split sharpened it: an opaque `expression` at least let the author `try/except` internally, whereas a per-token callable's exception escapes into the engine's blanket handler and one poison token wedges the arc indefinitely. The failure behaviour is **unchanged** (the arc is still treated as unsatisfiable); only the report is new. Reports are **edge-triggered and de-duplicated** per `(transition, place)`: selection re-runs on every enabling check, so a persistent fault fires once when it starts rather than once per `step()`. The edge is identified by the *tokens* the failing attempt saw — a later fault sharing none of them is a new event and reports again. Identifying it that way rather than by "the next successful selection clears it" matters in two directions: draining the place below `count` means selection is never reached, so a success never arrives and the arc would be muted permanently (and removing the offending token is the likeliest response to the report); and `step()` versus `is_quiescent()` evaluate different pools (only the latter sees cooling tokens), so a poison token awaiting a retry would otherwise have the two alternate — clear, report, clear, report — once per poll. An ordinary empty selection — a `filter` that legitimately rejects every token, or too few eligible tokens — is a normal "not enabled" and stays silent. The original exception is wrapped in a `RuntimeError` naming the transition and place, and chained as `__cause__`; the message also notes that a raising *certified* key permanently disables that arc's place key-index, so selection reverts to the per-firing sort even once the fault clears ([#34](https://github.com/philgresh/cpnx/issues/34)). Note the pre-existing `binding_priority_key` report is de-duplicated per pass, not edge-triggered. Resolves [#29](https://github.com/philgresh/cpnx/issues/29).

- **Persistent per-arc key-index — a deep keyed drain is now ≈ O(N log N) (was O(N² log N)).** A **certified** [`InputArc.key`][cpnx.InputArc] is now served from a `(key, seq)` min-heap maintained on the place across firings, instead of re-sorting the whole available pool on every firing. Keys are computed once, at deposit; entries are deleted lazily (an entry is stale once its `seq` leaves the ready set), exactly like the existing cooling heap. The engine reads only as many ordered tokens as the resolution can actually consume — `count` for a head-only binding, `binding_search_limit + count` for a searching policy — so a firing's cost no longer scales with the depth of the place. Measured on the `batch-triage` benchmark: **128 → 299 → 2441 µs/order** at 500/2000/20000 becomes **71 → 77 → 143**, i.e. per-order cost grows 2.0× across a 40× increase in depth (was 19×), a **17× speed-up at 20 000 orders**. This completes [#25](https://github.com/philgresh/cpnx/issues/25); see [`docs/adr/0004-arc-selection-key-filter.md`](docs/adr/0004-arc-selection-key-filter.md).

  Measured against the last published release (`cpnx==0.3.2` from PyPI, identical workload through each version's own API, interleaved repeats, consumption order verified identical): **5.3× / 10.6× / 21.9× faster** at 500 / 2 000 / 20 000 tokens, with growth across a 40× depth increase falling from 29.8× to 7.3×. That A/B also caught a regression the PR-1-vs-PR-2 comparison could not see: with the index unavailable, the arc-selection split had made a deep *certified*-key drain slower than 0.3.2 (3 053 vs 2 273 µs/order), because one C-level `sorted(tokens, key=k)` had become N interpreted per-token dispatches plus a decorate-sort. Since a certified callable is called directly regardless, `_order_available` now passes it straight to `sorted(key=...)` (and a certified `filter` straight to a comprehension), which restores the C-driven loop and leaves that path **1.4× faster** than 0.3.2 instead of 0.7× slower. This matters because it is the path the timed×key residual takes.

  **This is a pure optimisation with no semantic change.** `_order_available` remains the authority on ordering — it re-sorts whatever pool it is handed — so the index can only ever be a selection hint, never a source of order, and every read can decline. It declines, falling back to the per-firing filter+sort, whenever it cannot represent the whole available pool: an **uncertified** `key` (keying runs on the deposit path, which cannot host an unbounded callable), an **uncertified** `filter` (it could not be applied at pop, and applying it after a capped read would silently under-select), a **keying failure** (a `key` that raises, or keys that are mutually incomparable — the index disables itself rather than letting a bad key turn a `deposit()` into an exception), or **timed tokens present** (the index covers ready tokens only, and a cooling token never migrates into the ready set). The last of these is the timed×key residual: such a place keeps the previous cost, and no promotion pipeline was built. Reassigning `arc.key` after construction rebuilds the index rather than serving a stale ordering.

- **Closed-world certification (`cpnx.certification`).** A new module that proves a callable guard/expression is closed-world and provably terminating: a fixed whitelist of builtins/methods, iteration bounded by the argument, transitive certification of user helpers with cycle rejection, and immutable closure cells. Exposes `certify(func) -> Verdict` and `is_inline_safe(func) -> bool`; never raises for an un-certifiable callable.
- **Inline fast path.** A **certified** callable now runs **inline** — directly, under the engine lock, with no timeout — instead of via the `ThreadPoolExecutor`; an uncertified callable keeps the existing timeout-bounded executor path unchanged. This removes a ~90×-per-call dispatch cost on the hot path, since guards are re-evaluated per transition per `step()`, and per candidate binding under `RANDOM`/`PRIORITY`. Certification changes *how* a callable runs, never *whether* it is allowed. See [`docs/adr/0003-inline-execution-and-string-removal.md`](docs/adr/0003-inline-execution-and-string-removal.md).
- **Construction-time guard return-type check.** An annotated `Transition.guard` / `OutputArc.expression` is now verified to return `bool` at construction — a non-`bool` return annotation raises `TypeError` — while unannotated callables (including all lambdas) pass through unchecked. Enforces the CPN guard contract `Type[G(t)] = Bool`. See [`docs/adr/0002-guard-type-checking-scope.md`](docs/adr/0002-guard-type-checking-scope.md).

### Changed

- **`OutputArc.expression` renamed to `condition` (BREAKING).** Same type (`Callable[[list[Token]], bool] | None`), same skip-the-arc-on-`False` semantics, same construction-time annotated-`-> bool` check — this is a pure rename, not a behavior change. `OutputArc.on_color()` now builds a `condition=` internally. The rename makes the field name honest about the mechanism: on the output side an arc expression is, in every real use, a boolean *activation* predicate, not the token-selection mechanism the (now-split) input side used the same name for. Migration: `OutputArc(expression=p)` → `OutputArc(condition=p)`. See [`docs/adr/0004-arc-selection-key-filter.md`](docs/adr/0004-arc-selection-key-filter.md).
- **Guard contract documented.** A guard is a pure predicate over a candidate binding, evaluated an unbounded number of times, possibly under the engine lock — a side-effecting guard violates this contract. Effect-freedom is documented, not enforced; certification proves closed-world termination, not the absence of side effects.

### Notes

- **Executor batching stays deferred.** A certification hit-rate of **88.7%** across the combined corpus (81.7% of cpnx's own tests, 100% of a private downstream consumer) clears the ~80% go/no-go threshold, so inline certification already covers the common case and chunked-submit batching for uncertified callables is not being pursued now.

### Fixed

- **Transient-failure retries now honour the logical clock.** When a transition's action failed and its data token was rolled back for retry, the token's `available_at` was computed as `time.monotonic() + retry_delay` — the wall clock — while every other availability check (`Place.retrieve`/`can_retrieve`, `PacedResourcePlace` pacing, input-arc settle windows) compares against the net's `model_time`. On a net driven by `advance_time`, the rolled-back token therefore received a deadline of seconds-since-boot (order 10^6–10^7) against a logical clock typically near zero, so it could **never** become retrievable again: the retry was stranded in its source place indefinitely, and `run()` could return quiescent with that work still pending. The rollback path now applies `retry_delay` against the same clock as pacing and settle, resolved through the same `PetriNet._get_model_time_under_lock()` helper the deposit path already uses. Nets that never call `advance_time` are unaffected — the fallback reproduces the previous value exactly.

## [0.3.2] — 2026-07-11

### Added

- **`BindingPolicy.RANDOM`** — Enumerates the guard-satisfying bindings and selects one **uniformly at random**. Reproducible when the net is constructed with a `seed` (and `max_workers=1`); otherwise it varies run to run. Unlike `FIRST`, a guard-free `RANDOM` transition still selects among *all* eligible token groups (there is no guard-free fast path), so it always enumerates. Phase 2 of the plan in [`docs/adr/0001-combinatorial-binding-search.md`](docs/adr/0001-combinatorial-binding-search.md).
- **`BindingPolicy.PRIORITY`** — Enumerates the guard-satisfying bindings and selects the one **minimizing** `Transition.binding_priority_key`. Deterministic; ties fall to insertion order.
- **`Transition.binding_priority_key`** — Optional pure `Callable[[list[Token]], object]` mapping a candidate binding (its flat token list) to a comparable sort key for `PRIORITY`. `None` (default) means oldest-first — the minimum `Token.created_at` across the binding's **data** tokens (resource permits are excluded, so an ancient permit can't tie every candidate and collapse the choice to insertion order). Must be callable or `None` — a non-callable (e.g. a string expression, which is not supported) raises `TypeError` at assignment. A candidate whose key raises or is incomparable with the running best is skipped; if every candidate is skipped the first satisfying binding (insertion order) is used, so the firing path never disagrees with the enabling probe — and `on_error` fires (once per pass, off the lock) so a wholly-broken key is not silent. The key runs **inline under the engine lock with no timeout** (unlike callable guards, which use the expression pool), so it must be trivially cheap.

### Notes (search-limit clarification)

- `RANDOM`/`PRIORITY` over the limit only "select from a truncated prefix and fire" **when that prefix contains a satisfying binding**. A guarded `RANDOM`/`PRIORITY` transition whose only satisfying binding lies beyond the first `binding_search_limit` candidates finds nothing in the prefix and is disabled for that check — it can stall and let `run()` return quiescent exactly like `FIRST`. Raise `binding_search_limit` if this matters.
- **`PetriNet(seed=...)`** — Optional integer seed for the net's internal `random.Random`. When set it makes the run reproducible, driving **both** the scheduler's tie-break among equal-priority enabled transitions **and** `RANDOM` binding selection. Pair with `max_workers=1` for strict replay.

### Changed

- The scheduler's tie-break among equal-priority enabled transitions now draws from the net's `random.Random(seed)` instance instead of the global `random` module. Behavior is unchanged when unseeded, but the global `random.seed()` no longer influences cpnx scheduling — seed the net instead.

### Notes

- **Reproducibility is probe-independent.** Enabling/quiescence checks (`is_dead`, `is_quiescent`) use an existence-only probe that never draws the RNG, so a timing-dependent number of `run()` poll iterations cannot perturb a seeded `RANDOM` run.
- **Cost.** `RANDOM`/`PRIORITY` cannot short-circuit — they scan the whole (bounded) candidate set to sample or rank — so they are typically several times costlier than `FIRST` on the firing path. `binding_search_limit` still bounds the work; if the candidate space exceeds it, selection is over the first `limit` candidates (a **truncated prefix**) and `on_binding_search_exhausted` fires even though a binding is returned.
- The default policy remains `BindingPolicy.LEGACY`; `LEGACY`/`FIRST` behavior is unchanged from 0.3.1.

## [0.3.1] — 2026-07-10

### Added

- **`BindingPolicy`** — A new public enum (exported from `cpnx`) controlling how a transition resolves which input tokens bind it. `BindingPolicy.LEGACY` (the default) preserves the historical behavior: only the leading `count` tokens of each input place (FIFO / `InputArc.expression` ordering) are tested, with the guard evaluated once — subject to head-of-line (HoL) blocking. `BindingPolicy.FIRST` performs a **deterministic-complete binding search**, walking input-token combinations in stable insertion order and selecting the first combination whose guard holds; this fixes HoL blocking while remaining reproducible, and reduces to `LEGACY` (no search) when the transition has no guard.
- **`Transition.binding_policy`** — Optional per-transition policy (`BindingPolicy | None`, default `None`). `None` inherits the owning net's default, so binding search is **opt-in per transition or net-wide**.
- **`PetriNet(binding_policy=..., binding_search_limit=...)`** — The net-wide default policy (`binding_policy`, default `BindingPolicy.LEGACY`) and the cap on combinations tried per enabling check under `FIRST` (`binding_search_limit`, default `1000`).
- **`PetriNet.on_binding_search_exhausted`** — A new optional callback (`Callable[[str], None] | None`) fired **outside** the engine lock (so it may call back into the net) with the transition name when a `FIRST` search reaches `binding_search_limit` without finding a satisfying binding; the transition is treated as disabled for that check, never a silent hang. Exhaustions are de-duplicated *within* a single enabling pass before dispatch; a busy `run()` loop still fires it once per `step()`/`is_quiescent()` iteration, so keep the callback cheap and debounce on your side if needed. `binding_search_limit` must be `>= 1` (validated in the constructor).

### Notes

- The default remains **`BindingPolicy.LEGACY`**, so existing nets keep their historical enabling/consumption behavior; HoL blocking is only fixed when `FIRST` is explicitly selected. Two deliberate, engine-wide refinements to the resolve/consume path apply even under `LEGACY`, so behavior is not strictly byte-for-byte for two edge cases: (1) an input arc's selection **expression is now evaluated once per firing** (at resolution) rather than a second time at consumption — nets relying on a stateful/nondeterministic `InputArc.expression` observe the single evaluation; (2) token **consumption now goes exclusively through `Place.retrieve_specific`** (by token id) for every arc, so third-party `Place` subclasses that override `retrieve`/`retrieve_all` but not `retrieve_specific` no longer see their overrides invoked during firing.
- Under `FIRST`, `binding_search_limit` bounds the search's time **and** memory (each arc's candidate stream is truncated to `binding_search_limit + 1` groups before the Cartesian product is formed), and with a callable guard also bounds the lock-hold time to roughly `binding_search_limit × expr_timeout_secs`. Because an exhausted search counts as "disabled", a net whose only satisfiable binding lies past the limit can reach quiescence with that work still pending, signalled only via `on_binding_search_exhausted`.
- Resource (`ResourcePlace`/`PacedResourcePlace`) permit arcs contribute `C(capacity, count)` interchangeable combinations to the search; list resource arcs before data arcs in `Transition.inputs` (and/or raise the limit) so the data dimension varies first. See `BindingPolicy` for details.
- This is the **opt-in realization of the combinatorial binding** that the 0.3.0 **Notes** section had said was intentionally not implemented. The search walks the `itertools.product` of each arc's `count`-sized combinations and short-circuits on the first satisfying binding; each dimension is truncated to `binding_search_limit + 1` groups first, so both work and memory stay bounded by the limit rather than by `C(N, count)`. It is Phase 1 of the plan in [`docs/adr/0001-combinatorial-binding-search.md`](docs/adr/0001-combinatorial-binding-search.md).
- Planned follow-ups: **Phase 2** (`RANDOM`/`PRIORITY` selection policies) and **Phase 3** (flip the default to complete binding search at a major version bump).

## [0.3.0] — 2026-06-30

### Added

- **`SandboxEvaluator.compile_expression`** — Validates a string expression via the static AST security walk and returns a compiled `eval`-mode code object. Results are cached by source text, so an identical expression is parsed and compiled at most once.
- **`SandboxEvaluator.evaluate_compiled`** — Evaluates a pre-compiled code object against a context dictionary, skipping the parse/compile step.
- **`SandboxEvaluator.maybe_compile`** — Compiles a value if it is a string expression, otherwise returns `None` (for callables/`None`), centralizing the string-vs-callable rule.
- **Benchmarks** — `benchmarks/bench_enablement.py` (native stdlib, no dependencies) plus a `benchmarks/README.md` documenting methodology for pre/post performance comparison.

### Changed

- **Compile-once string expressions** — Guard and arc string expressions are now parsed, security-walked, and compiled once at `Transition`/`InputArc`/`OutputArc` construction time and reused on every enablement check, instead of re-parsing/re-compiling on every `SandboxEvaluator.evaluate()` call. The engine's `_is_transition_enabled` hot path reuses the compiled object via `evaluate_compiled`. End-to-end enablement checks on the string-guard path improved roughly 7–8×; the isolated compile path is ~215× faster. `SandboxEvaluator.evaluate()` is preserved as a thin, cached wrapper — the public API and `PermissionError` semantics are unchanged.
- **Eager validation of string expressions** — A malformed or forbidden **string** guard/arc expression now raises `PermissionError` at `Transition`/`InputArc`/`OutputArc` construction (and on reassignment) rather than being silently treated as a disabled transition at run time. Compiled objects stay in sync with the live `guard`/`expression`, so post-construction reassignment recompiles rather than evaluating a stale predicate.

### Notes

- Lazy `itertools.product` binding enumeration (a commonly suggested optimization) was intentionally **not** implemented: the engine resolves a single deterministic binding per transition (no Cartesian product across input places), so there is no combinatorial explosion to short-circuit.

## [0.1.2] — 2026-06-26

### Added

- **`action_timeout_secs`** — New optional field on `Transition`. When set, the engine
  enforces a wall-clock deadline on the action callable. Timed-out actions trigger
  atomic rollback (all consumed tokens returned to source; data tokens with a one-second
  `available_at` delay to prevent livelock) and fire the `on_error` callback with a
  descriptive `RuntimeError`. Uses a dedicated secondary executor (`cpnx-action`) to
  avoid nested-future deadlock. The underlying OS thread is not killed; callers must
  apply native I/O timeouts inside their actions to prevent zombie thread accumulation.

### Fixed

- **Encapsulation** — `SubstitutionTransition` no longer writes a `_parent_transition`
  back-reference onto the child `PetriNet` instance. Double-mapping prevention is now
  tracked entirely on the parent side via a class-level `WeakSet`, keeping subnets
  fully agnostic of their parents.
- **Atomicity** — On transition failure, all consumed tokens (resource *and* data) are
  now returned to their original source places, preserving the formal Marking exactly.
  Previously, data tokens were routed to a dead-letter `error_place`, which altered
  the Marking in a way that could not be modelled as a clean rollback. Data tokens
  receive a one-second `available_at` delay on return to prevent livelock when an
  action raises persistently. The `on_error` callback continues to fire for
  observability.
- **Sandbox purity** — `verify_callable_purity` now inspects `FunctionDef` default
  argument values. Mutable literals (`list`, `dict`, `set`) as parameter defaults
  raise `PermissionError`, closing a loophole that permitted hidden persistent state
  between transition firings.
- **Sandbox deadlock** — `SandboxEvaluator.evaluate` now blocks all iteration
  constructs: `while`, `for`, and `async for` loops, as well as list, dict, and set
  comprehensions and generator expressions. These could previously hold the engine lock
  indefinitely; comprehensions were the critical gap as they are `ast.ListComp` nodes,
  not `ast.For`, and would have bypassed a loop-only check.
